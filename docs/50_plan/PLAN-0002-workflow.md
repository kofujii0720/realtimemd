# PLAN-0002 開発ワークフロー・判断基準

## 1. セッション運用ルール
- 1セッション = 1成果物。完了したら必ず `/clear` を実行してコンテキストをクリーンにする。
- コンテキスト引きずりによる設計無視や自己推測を防ぐ。

## 2. 実装およびテスト順序の原則
1. 実装前にE2E/単体テストの観点消化表をコードより先に出力させる。
2. 観点消化表に必須 (○) の漏れがないことを確認してからコードを書き始める。
3. コード変更後は即座に `npm run check` または `node scripts/check-docs.mjs` を実行し、全センサーの PASS を確認する。

## 3. 並列化・ブランチ判断
- 単一マイルストーン内での並列エージェント実行は、対象ファイルおよび共有ファイルへのコンフリクトがない独立作業（例: API実装とE2Eテスト作成）に限定する。
- `main` ブランチ保護および直コミット禁止を徹底する。
