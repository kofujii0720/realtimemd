# アンチパターン集 (anti-patterns.md)

全エージェントが作業時に毎回確認すべき共通注意事項。過去の失敗から得られた教訓。

## 1. 設計・参照のアンチパターン
- **推測での仕様埋め**: 不明な仕様や未確定要件を勝手に判断しない。必ず `要確認事項` セクションに記述して人間に確認する。
- **文章による参照**: 「〜画面の検索項目」などと書かず、`SCR-0101.item.search_word` と ID 参照する。
- **エラーコードの新設**: API実装時に設計書「2.3 エラー」に未定義のコード（E-XXXX-YYY）をコード側で勝手に新設しない。

## 2. 実装のアンチパターン
- **日付の直接生成**: ユースケース・ドメイン層で `new Date()` や `datetime.now()` を呼ばない。現在時刻は引数 `now` で受ける。
- **エラーの握りつぶし**: exceptions を catch して無言で pass や return None にしない。ログ出力の上、定義済みエラーに変換してスローする。
- **設計書の同時改変**: コード実装のついでに `docs/` を書き換えない。設計変更は必ず設計専用のセッションで行う。
